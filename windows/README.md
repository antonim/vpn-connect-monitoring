# VPN Connect Monitoring

Следит за тем, что VPN-подключение поднято в рабочее время, показывает
уведомление при обрыве и ведёт журнал состояния — чтобы потом увидеть на
графике, когда именно связь пропадала. Живёт значком в системном трее.

## Для коллег: установка

**[Скачать VpnConnectMonitoring.exe](https://github.com/antonim/vpn-connect-monitoring/releases/latest)** — один файл, ничего доустанавливать не нужно.

1. Запустить `VpnConnectMonitoring.exe`.
2. При первом запуске сразу откроется окно настроек. Выбрать своё
   VPN-подключение из списка, при необходимости поправить часы и дни.
3. Нажать **Установить в систему** — программа скопирует себя в профиль
   пользователя и пропишет автозапуск при входе в Windows.

Права администратора не нужны: всё пишется в `%LOCALAPPDATA%` и `HKCU`.
Устанавливать .NET не требуется — .NET Framework 4.8 уже входит в Windows 10
(версии 2004 и новее) и Windows 11.

При первом запуске SmartScreen может показать «Windows защитила ваш
компьютер» — файл не подписан цифровым сертификатом. Кнопка
«Подробнее» → «Выполнить в любом случае».

## Что настраивается

| Параметр | Назначение |
|---|---|
| VPN-подключение | Имя из списка RAS-подключений; можно вписать вручную |
| Рабочие часы | Окно наблюдения, допускается переход через полночь (22:00–06:00) |
| Дни недели | По умолчанию Пн–Пт |
| Интервал опроса | 10–3600 секунд, по умолчанию 60 |
| Не повторять чаще | Пауза между повторными уведомлениями, 0 — при каждой проверке |
| Уведомлять о восстановлении | Сообщать, когда связь вернулась |
| Звуковой сигнал | Свой звук при обрыве и восстановлении |
| Наблюдение включено | Общий выключатель |

Настройки лежат в `%APPDATA%\VpnConnectMonitoring\config.ini` — обычный
текстовый файл, его можно подготовить заранее и раздать команде.

Значок в трее меняет цвет: зелёный — VPN поднят, красный — оборван,
серый — вне рабочего времени, пауза или наблюдение выключено.

В меню значка продублированы частые действия: журнал, настройки, проверка
сейчас, **пауза на 1 час** и переключатель **«Звуковой сигнал»**. Последний
правит ту же настройку, что и флажок в окне, и сразу пишется в конфиг.

## Журнал и график

Открывается двойным щелчком по значку в трее, из меню значка или кнопкой
**Журнал…** в настройках.

Лента показывает состояние за выбранный период (24 часа, 3 дня, 7 или 30
дней): зелёный — связь была, красный — обрыв, серый — наблюдение не велось.
При наведении курсора выводится состояние на конкретный момент. Ниже —
доступность в процентах, число обрывов, суммарное и максимальное время без
связи, а также таблица обрывов с началом, окончанием и длительностью.

Данные в `%APPDATA%\VpnConnectMonitoring\history.csv`, формат
`дата-время;состояние` (`up` / `down` / `idle`), хранение 30 дней.

Пишется не каждая проверка, а смена состояния плюс «сердцебиение» раз в
5 минут. Это держит файл компактным и, что важнее, позволяет отличить
«связь была всё время» от «программа не работала»: разрыв между соседними
записями больше 12 минут трактуется как отсутствие наблюдения. Благодаря
этому выключение компьютера, сон и аварийное завершение не превращаются
в ложный зелёный участок на графике.

## Сборка

```
powershell -ExecutionPolicy Bypass -File build.ps1
```

Результат — `build\VpnConnectMonitoring.exe`, около 85 КБ, без внешних
зависимостей.

Сборка идёт компилятором `csc.exe` из состава Windows, ставить .NET SDK не
нужно. Он поддерживает **только C# 5**, поэтому в исходниках нет
интерполяции строк, `?.`, `nameof` и прочего более позднего синтаксиса.

Значок приложения генерируется скриптом сборки в классическом DIB-формате:
PNG-сжатые кадры внутри `.ico` компилятор отвергает.

Проверить вёрстку окон, не запуская приложение (расположение элементов
задано абсолютными координатами, поэтому после правок форм это полезно):

```
powershell -ExecutionPolicy Bypass -File tools\render-settings.ps1 -Which settings
powershell -ExecutionPolicy Bypass -File tools\render-settings.ps1 -Which history
```

Скрипты сборки сохранены в UTF-8 **с BOM**: без него Windows PowerShell 5.1
читает кириллицу в них как ANSI и падает на разборе строк.

## Как определяется статус VPN

Через `NetworkInterface`: подключённое RAS-соединение поднимает сетевой
интерфейс со своим именем, в отключённом состоянии интерфейс исчезает.

Вариант с `RasEnumConnections` отвергнут намеренно — размер структуры
`RASCONN` менялся между версиями Windows, и при несовпадении `dwSize` вызов
возвращает `ERROR_INVALID_SIZE`.

Список доступных подключений читается из телефонной книги RAS
(`rasphone.pbk`) — пользовательской и общесистемной.

## Уведомления и звук

Используется WinRT (`ToastNotificationManager`) с собственным
AppUserModelID `VpnConnectMonitoring`. Приложение при старте само:

1. регистрирует AppID в `HKCU\SOFTWARE\Classes\AppUserModelId`;
2. вызывает `SetCurrentProcessExplicitAppUserModelID`;
3. создаёт ярлык в меню «Пуск» со свойством `System.AppUserModel.ID`.

Третий пункт — документированное требование Microsoft к настольным
(не упакованным) приложениям: по ярлыку оболочка связывает процесс с
AppUserModelID. Пропускать его не стоит, даже если без него работает.

Баннер показывается с `duration="long"` — около 25 секунд вместо пяти.
Пять секунд обрыв VPN пропускается на раз, это проверено на практике.

Звук у самого уведомления отключён (`<audio silent="true"/>`), вместо него
играет свой сигнал: обрыв — три нисходящих тона, повторённые дважды,
восстановление — короткий восходящий. Волна синтезируется в памяти, файлов
`.wav` рядом с exe не нужно. Системные схемы намеренно не используются —
их слух отфильтровывает как фон.

Типы WinRT грузятся рефлексией (`Type.GetType` с
`ContentType=WindowsRuntime`), потому что дать ссылку на `Windows.winmd`
во время компиляции нечем — Windows SDK для сборки не нужен.

Если WinRT почему-то недоступен, происходит откат на воздушную подсказку
`NotifyIcon`, которую Windows 10/11 тоже показывает как toast.

### Отладка уведомлений

Показ уведомления — операция без обратной связи: `Show()` возвращает `void`
и молчит, когда система отбрасывает уведомление. Поэтому каждый шаг
пишется в `%APPDATA%\VpnConnectMonitoring\debug.log`.

Проверить, приняла ли система уведомление, можно объективно — по времени
в реестре:

```
HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Notifications\Settings\VpnConnectMonitoring
    LastNotificationAddedTime   (FILETIME, сверять с debug.log)
```

Само по себе наличие этого ключа ни о чём не говорит и появляется с
задержкой — ориентироваться нужно именно на метку времени.

## Удаление

Кнопка **Удалить из системы** в окне настроек: снимает автозапуск, удаляет
ярлык из «Пуска» и установленную копию. Настройки и журнал сохраняются.

Полностью, включая настройки, журнал и регистрацию уведомлений:

```
powershell -Command "Remove-Item \"$env:APPDATA\VpnConnectMonitoring\" -Recurse -Force; Remove-Item 'HKCU:\SOFTWARE\Classes\AppUserModelId\VpnConnectMonitoring' -Recurse -Force"
```
