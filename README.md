# VPN Connect Monitoring

Следит за тем, что VPN-подключение поднято в рабочее время, предупреждает
уведомлением со звуком, когда связь отваливается, и ведёт журнал — чтобы
потом увидеть на графике, в какой момент это произошло.

Значок в трее или в строке меню, никаких серверов и учётных записей:
всё работает локально.

Права администратора не нужны ни в одной из систем: настройки
и автозапуск пишутся в профиль пользователя.

Для macOS собирается образ диска: двойной щелчок открывает окно, где
приложение перетаскивают на ярлык «Программы». Рядом с ними лежит папка
«Для терминала» с `install.sh`, диагностикой и кодом — она нужна только
тем, кому нужна команда в терминале. Тот же набор выкладывается и
архивом `.tar.gz`.

### Первый запуск на macOS

Приложение не подписано в Apple, поэтому Gatekeeper блокирует его один раз.
На macOS 15 и новее обход правым щелчком убран: откройте «Системные
настройки» → «Конфиденциальность и безопасность» и нажмите «Всё равно
открыть». На macOS 14 и старше — правый щелчок по значку приложения → «Открыть».

Затем разрешите уведомления: «Системные настройки» → «Уведомления» →
«VPN Connect Monitoring» → включить «Допуск уведомлений», стиль оповещений
поставить «Предупреждения». Стиль имеет значение: «Баннеры» исчезают
с экрана сами через несколько секунд, и обрыв связи легко пропустить.
Программа просит «Предупреждения» по умолчанию, но выбор человека для
macOS главнее, и переопределить его она не может.

Отдельно про python3: на macOS без установленных Command Line Tools
`/usr/bin/python3` — это заглушка, которая при первом вызове открывает окно
установки на полтора гигабайта. Запускающие скрипты обращаются к ней только
после проверки `xcode-select -p`, а если питона в системе нет вовсе —
показывают окно с тем, что нужно поставить.

## Что умеет

- Опрос VPN по расписанию: рабочие часы, дни недели, интервал 10–3600 секунд.
- Уведомление при обрыве со своим звуком — нисходящий мотив, не похожий на
  системные звуки. При восстановлении связи — короткий восходящий.
- Журнал состояния и график: когда именно пропадала связь, доступность
  в процентах, таблица обрывов с длительностью.
- Настройка частоты повторных предупреждений, пауза на час, переключатель
  звука прямо в меню значка.
- Список доступных VPN-подключений приложение собирает само — искать имена
  вручную не нужно.

## Устройство

Linux и macOS делят один код на Python: различаются только адаптеры —
определение VPN, уведомления, звук, автозапуск и значок. Windows-версия
отдельная, на C# с WinForms и WinRT.

Совпадают у всех трёх формат конфига и журнала, логика расписания и правила
построения графика.

| | Windows | Linux | macOS |
|---|---|---|---|
| Язык | C# 5, WinForms | Python 3, GTK 3 | Python 3, AppKit через ctypes |
| Сборка | `csc.exe` из состава Windows | `dpkg-deb` | `hdiutil`, `tar` |
| Результат | exe, 86 КБ | deb, 20 КБ | dmg, 185 КБ |
| Зависимости у пользователя | нет | python3, libnotify-bin | python3 |

Все три сборки намеренно обходятся тем, что уже есть в системе: ни .NET SDK,
ни виртуальных окружений, ни сторонних библиотек не требуется.

### Как это устроено на macOS

Значок в строке меню и уведомления обращаются к AppKit напрямую через
`ctypes` — это модуль `objc_bridge` рядом с остальным кодом. Обычный для
этого PyObjC не подходит: с macOS он не поставляется — Apple убрала его
вместе с системным Python 2.7 в macOS 12.3, — в Command Line Tools его нет,
а в питон из Homebrew pip не пускает, потому что тот помечен
externally-managed. Виртуальное окружение ради одного значка потребовало бы
сети при установке и ломалось бы при каждом обновлении интерпретатора.

Уведомления показываются самой программой, а не через `osascript`. У
`osascript` два изъяна: сообщение приходит от имени «Script Editor», и если
уведомления этому приложению не разрешены, оно не приходит вовсе — причём
вызов при этом завершается успешно. Молчаливый отказ хуже явного, поэтому
`osascript` оставлен запасным путём.

Чтобы центр уведомлений показывал имя и значок программы, а не «Python»
с его ракетой, процесс подменяет себе `-[NSBundle bundleIdentifier]`:
Python во фреймворковой сборке всегда объявляет главным бандлом свой
`Python.app`, и это не обходится ни расположением файлов внутри пакета,
ни символическими ссылками, ни копией бинарника.

Исполняемым файлом пакета `.app` обязан быть Mach-O: приложение, у
которого на этом месте лежит скрипт, macOS 15 не открывает вовсе —
сначала предлагает поставить Rosetta, не сумев определить архитектуру,
затем возвращает `-10669`. Компилировать при этом ничего не нужно:
`osacompile` входит в macOS и собирает пакет вокруг стандартного
applet'а, готового под обе архитектуры, а тот запускает обычный скрипт
из `Contents/Resources`. Два ключа, которые `osacompile` при этом
проставляет, приходится убирать: `LSMinimumSystemVersionByArchitecture`
перечисляет один `x86_64` и снова наводит систему на мысль про Rosetta,
а объяснения доступа к камере и контактам всплыли бы в запросах
приватности на ровном месте.

Значок рисуется при сборке скриптом `macos-app/make-icon.py` средствами
стандартной библиотеки: PNG пишется вручную, фигуры задаются функциями
расстояния со знаком — сглаживание получается из доли пикселя внутри
фигуры, без передискретизации. В `.icns` его собирают системные `sips`
и `iconutil`. В репозитории готового значка нет: несколько килобайт
скрипта вместо сотни у двоичного файла, и рисунок не может разойтись
с кодом, который его создаёт.

В самом уведомлении значок остаётся питоновским: центр уведомлений берёт
картинку у приложения, которое сообщение отправило, а отправляет его
Python. Подменить её можно только непубличным методом `set_identityImage:`,
который вылетает с исключением даже там, где `respondsToSelector:`
отвечает утвердительно, — для программы, чья работа предупреждать
об обрывах, падение вместо предупреждения хуже чужой картинки. В Finder,
Dock и «Системных настройках» значок свой.

Архив macOS весит больше остальных, потому что несёт пакет `.app`, код
внутри которого — вторая копия, и собранный значок во всех размерах. Символической ссылкой на общий `lib` обойтись
нельзя: она сломается, как только приложение перенесут в «Программы».
