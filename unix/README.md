# VPN Connect Monitoring — Linux и macOS

Следит за тем, что VPN поднят в рабочее время, предупреждает уведомлением
со звуком при обрыве и ведёт журнал, по которому строится отчёт с графиком.

Обе системы используют один и тот же код на Python. Различаются только
адаптеры: определение VPN, уведомления, звук, автозапуск и значок.

## Установка на Ubuntu / Debian

**[Скачать .deb](https://github.com/antonim/vpn-connect-monitoring/releases/latest)**, затем:

```bash
sudo apt install ./vpn-connect-monitoring_*_all.deb
```

Именно `apt`, а не `dpkg -i`: он сам подтянет зависимости.

Дальше запустить из меню приложений или командой `vpn-connect-monitoring`.
Откроется окно настроек — выбрать своё подключение, при необходимости
поправить часы и дни, поставить галочку «Запускать при входе в систему».

## Установка на macOS

**[Скачать архив](https://github.com/antonim/vpn-connect-monitoring/releases/latest)**, затем:

```bash
tar -xzf vpn-connect-monitoring-*-macos.tar.gz
cd vpn-connect-monitoring-*/
./install.sh
```

Установка идёт в `~/.local`, права администратора не нужны.

### Про PyObjC

Значок в строке меню требует PyObjC. Тут есть ловушка: PyObjC входит
в **системный** `/usr/bin/python3`, но если в `PATH` первым стоит питон
из Homebrew или pyenv — а так бывает часто, — берётся он, и PyObjC там нет.

Launcher это учитывает: он перебирает интерпретаторы и выбирает тот,
в котором PyObjC действительно импортируется. Ставить и настраивать
ничего не нужно, пока хотя бы один подходящий питон в системе есть.

Если ни одного не нашлось, есть два пути:

```bash
xcode-select --install                                  # системный python3
# или добавить PyObjC в тот питон, который используется:
python3 -m pip install pyobjc-framework-Cocoa
```

Режимы `--daemon`, `--list` и `--report` работают без PyObjC вообще.

Первый запуск и включение автозапуска:

```bash
~/.local/bin/vpn-connect-monitoring --list        # посмотреть подключения
~/.local/bin/vpn-connect-monitoring               # запустить
```

Значок появится в строке меню. Автозапуск включается LaunchAgent'ом —
см. раздел «Автозапуск» ниже.

При первом уведомлении macOS спросит разрешение на показ. Если случайно
отказать, включить обратно можно в «Системные настройки» → «Уведомления».

## Выбор подключения

Список приложение собирает само, вручную ничего искать не нужно:

```bash
vpn-connect-monitoring --list
```

**Linux.** Интерфейсы `wg*`, `tun*`, `tap*`, `ppp*` и подключения
NetworkManager типа `vpn`/`wireguard`. Подключения NetworkManager попадают
в список даже когда выключены — иначе выбрать нужное было бы нельзя.

**macOS.** Службы сетевых подключений из «Системных настроек»
(`scutil --nc`) — это встроенные IKEv2, IPsec и L2TP. Плюс интерфейсы
`utun` с назначенным адресом — их поднимают WireGuard, OpenVPN
и Tunnelblick.

Пустые `utun` из списка отбрасываются намеренно: macOS держит несколько
таких интерфейсов под свои службы вроде Private Relay и Handoff, и без
фильтра список состоял бы в основном из них.

В конфиге цель записывается с префиксом:

| Префикс | Пример | Где применяется |
|---|---|---|
| `iface:` | `iface:wg0`, `iface:utun4` | обе системы |
| `nm:` | `nm:office-vpn` | Linux, NetworkManager |
| `nc:` | `nc:Office VPN` | macOS, службы подключений |

## Автозапуск

**Linux** — файл в `~/.config/autostart`, галочка есть в окне настроек.

**macOS** — LaunchAgent в `~/Library/LaunchAgents`. Включить:

```bash
python3 -c "import sys; sys.path.insert(0,'$HOME/.local/lib'); from vpnmon import autostart; autostart.enable()"
```

Агент создаётся с `RunAtLoad`, но без `KeepAlive`: перезапускать
приложение, которое вы сами закрыли через меню, было бы навязчиво.

## Режим без графики

Для машины без рабочего стола или для systemd:

```bash
vpn-connect-monitoring --daemon
```

GTK и PyObjC в этом режиме не импортируются вовсе. Уведомления всё равно
отправляются, если в сессии есть чем; журнал ведётся в любом случае.

Пример user-юнита `~/.config/systemd/user/vpn-connect-monitoring.service`:

```ini
[Unit]
Description=VPN Connect Monitoring
After=network.target

[Service]
ExecStart=/usr/bin/vpn-connect-monitoring --daemon
Restart=on-failure

[Install]
WantedBy=default.target
```

```bash
systemctl --user enable --now vpn-connect-monitoring
```

## Журнал и отчёт

Пункт **«Журнал подключения…»** в меню значка строит HTML-отчёт и открывает
его в браузере. То же самое из терминала:

```bash
vpn-connect-monitoring --report --open
```

В отчёте лента состояний за 24 часа, 3, 7 и 30 дней с переключением на
месте, доступность в процентах, суммарное и максимальное время без связи и
таблица обрывов. Файл самостоятельный — его можно переслать администратору.

Отчёт сделан в HTML, а не нарисован в окне, намеренно: так он работает и на
машине без графики, и его удобно отправлять как есть.

## Файлы

| Путь | Что это |
|---|---|
| `~/.config/vpn-connect-monitoring/config.ini` | Настройки, обычный текст |
| `~/.config/vpn-connect-monitoring/history.csv` | Журнал, `дата-время;состояние` |
| `~/.config/vpn-connect-monitoring/report.html` | Последний построенный отчёт |

Каталог `~/.config` используется и на macOS — вопреки тамошнему обычаю
хранить всё в `~/Library/Application Support`. Так конфиг и журнал
переносятся между системами без правок, а формат совпадает ещё
и с Windows-версией.

## Сборка

```bash
./build-deb.sh      # пакет для Ubuntu/Debian
./build-macos.sh    # архив для macOS
```

`build-deb.sh` требует только `dpkg-deb` из базовой Ubuntu. Пакет
архитектурно-независимый: внутри Python и текстовые файлы.

GTK и индикатор вынесены в `Recommends`, а не `Depends`: на сервере нужен
только `--daemon`, тянуть туда библиотеки рабочего стола незачем. Apt
в Ubuntu ставит `Recommends` по умолчанию, поэтому на настольной машине
всё приедет само.

`build-macos.sh` делает `.tar.gz` с `install.sh` и работает на любой
системе, не только на Mac. Формат выбран вместо `.pkg` сознательно:
`pkgbuild` есть только на macOS, а архив собирается где угодно.

## Устройство адаптеров

| | Linux | macOS |
|---|---|---|
| Состояние VPN | `/sys/class/net` + `nmcli` | `scutil --nc` + `ifconfig` |
| Уведомления | `notify-send` | `terminal-notifier`, иначе `osascript` |
| Звук | `pw-play` / `paplay` / `aplay` | `afplay` |
| Значок | AppIndicator (GTK) | `NSStatusItem` (PyObjC) |
| Автозапуск | `~/.config/autostart` | LaunchAgent |

Четыре решения, которые стоит понимать при доработке:

**Состояние интерфейса на Linux определяется по флагам, а не по
`operstate`.** У `tun`- и `wireguard`-интерфейсов `operstate` сплошь и
рядом равен `unknown` даже когда связь есть, и сравнение с `up` давало бы
постоянную ложную тревогу.

**На macOS `utun` без адреса не считается VPN.** Система держит такие
интерфейсы под свои нужды постоянно, и их наличие ничего не говорит
о подключении.

**Уведомления об обрыве на Linux отправляются с `--urgency critical`.**
В GNOME такой баннер висит, пока его не закроют. Исчезающий баннер — ровно
та причина, по которой обрывы пропускались в Windows-версии.

**На macOS предпочитается `terminal-notifier`, если он установлен.**
У `osascript` два ограничения: уведомление приходит от имени «Script
Editor», а не от нашей программы, и его нельзя сделать несмахиваемым.

## Чего на macOS пока нет

**Окна настроек.** Пункт «Настройки…» открывает `config.ini` в текстовом
редакторе. Формат простой и описан выше, а после правки настройки
подхватываются пунктом «Проверить сейчас». Полноценное окно на PyObjC —
заметный объём кода, который не на чем было проверить.
